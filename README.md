# Агрегатор нерухомості — Івано-Франківськ

Збирає оголошення про **продаж квартир в Івано-Франківську** з п'яти джерел,
нормалізує їх в єдину схему й показує у веб-інтерфейсі з сортуванням і фільтрами.

## Швидкий старт

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium      # потрібен лише для OLX
cp .env.example .env                       # за бажанням: ключ для LLM-фолбеку

.venv/bin/python cli.py scrape             # зібрати дані
.venv/bin/python cli.py serve              # http://127.0.0.1:8000
```

## Джерела та спосіб доступу

Кожне джерело перевірялося окремим скриптом у `probes/` до того, як потрапило
в пайплайн. Спосіб доступу обраний під конкретний сайт:

| Джерело | Доступ | Що дає |
|---|---|---|
| **DIM.RIA** | JSON `/node/searchEngine/v2/` + `/realty/data/{id}`, далі `__INITIAL_STATE__` сторінки | ціна, площа, кімнати, вулиця, район, поверх, опис, теги; зі сторінки — «стан квартири», тип нерухомості, рік будівництва |
| **LUN** | RSC-payload Next.js `/sale/if/flats` + картка rieltor.ua | ціна, $/м², кімнати, площа, рік, опис, `withoutRenovation`; зі сторінки-першоджерела — поле «Загальний стан квартири» |
| **OLX** | рендер у Chromium (Playwright): стрічка + сторінка оголошення | ціна, площа, дата; зі сторінки деталей — кімнати, поверх, вид об'єкта, опис |
| **flombu** | JSON:API `/uk/estate_deal_sales.json?filter[...]` | ціна, площа, адреса, координати |
| **blago** | статичний HTML каталогу планувань | ЖК, площа, кімнати; ціна лише як «від N грн/м²» |

Ідентифікатори, з'ясовані на етапі верифікації: DIM.RIA `state_id=15`, `city_id=15`;
LUN — код міста `if`.

### Обмеження, які варто знати

- **OLX** блокує HTTP-клієнти (CloudFront віддає 403), тому працює лише через
  реальний браузер. Це звичайний Chromium із локаллю `uk-UA` — без
  stealth-патчів і підміни відбитків.
- **flombu** ігнорує гео-фільтр і повертає всю область, тому остаточний відбір
  міських лотів робиться на нашому боці; корисних записів на сторінку небагато.
- **blago** не має реальної пагінації (`/plannings/page/N/` віддає той самий
  набір), тому обходимо тематичні розділи каталогу й дедуплікуємо. Ціни за
  об'єкт забудовник не публікує — загальна ціна рахується як
  `площа × грн/м²` і позначається прапорцем `price_estimated`.
- **LUN**: розділ новобудов — це каталог ЖК без даних по квартирах, тому
  первинний ринок беремо з DIM.RIA, flombu і blago.

## Схема даних

`realty/models.py`, таблиця `listings` (SQLite через SQLAlchemy):

| Поле | Опис |
|---|---|
| `price`, `currency` | ціна у валюті оголошення |
| `price_usd`, `price_uah` | єдина шкала для сортування (курс НБУ, з резервом у `.env`) |
| `rooms`, `area_total` | кімнати, загальна площа |
| `price_per_sqm` | $/м² — з джерела або розрахунок |
| `location`, `district` | адреса/район в Івано-Франківську |
| `published_at` | дата публікації |
| `market_type` | `primary` (новобудова) / `secondary` / `unknown` |
| `condition` | `renovated` (з ремонтом) / `needs_repair` (без ремонту) / `unknown` |
| `original_url` | пряме посилання на оголошення |
| `source`, `external_id` | джерело й ключ дедуплікації |
| `price_estimated`, `detail_enriched`, `llm_extracted` | прапорці якості даних: ціна є оцінкою; поля дібрані зі сторінки деталей; поля дібрані моделлю |

Ключ ідентичності — пара `(source, external_id)`; повторний прогін оновлює
наявні записи, а не дублює їх.

> **`original_url` навмисно не унікальний.** LUN — агрегатор і віддає посилання
> на інші сайти, зокрема на olx.ua, тож те саме посилання законно приходить від
> двох джерел. Поки на колонці стояв `UNIQUE`, повний збір LUN падав на
> конфлікті. Однакові URL зводить дедуплікація — це найнадійніший з її сигналів.

Записи пишуться пачками по 200, і **кожен запис ізольований точкою
збереження**. Без цього одна помилка цілісності отруювала транзакцію: усі
наступні `upsert` падали, підсумковий `commit` теж, і пакет відкочувався
цілком — на повному прогоні так було втрачено понад 5 000 зібраних оголошень
LUN через єдиний конфлікт посилань.

### Історія цін

Таблиця `price_events` фіксує зміну ціни в оголошенні — і лише зміну:
повторний прогін із тією самою ціною запису не створює, інакше історія
перетворилась би на журнал прогонів. Для майстер-запису історія всіх його
оголошень зводиться в одну: `/api/properties/{id}/prices`.

## Архітектура

```
cli.py                 scrape / serve / stats
realty/
  config.py            гео-константи, темп запитів, налаштування джерел
  fetcher.py           HTTP-клієнт (ретраї, кеш, ліміт темпу) + рендер у Chromium
  normalize.py         парсери ціни/площі/кімнат/дат, класифікатори, гео-фільтр
  llm.py               резервне вилучення через Claude API (structured output)
  sources/             по модулю на джерело, спільний контракт у base.py
  pipeline.py          збір -> LLM-фолбек -> upsert
  web/                 FastAPI + Jinja2
probes/                ізольовані скрипти верифікації джерел
tests/                 регресійні тести парсерів
```

### Три рівні вилучення

Резервні рівні вмикаються за прогалинами, і прогалини поділені на два види
(`Pipeline._gaps`):

- **критичні** — `price`, `rooms`, `area_total`. Запускають обидва резервні рівні,
  включно з платним викликом моделі.
- **бажані** — `market_type`, `condition`. Запускають лише рівень 2: зазирнути
  на сторінку оголошення дешево, а платити за них викликом моделі не варто.

Сторінка оголошення завантажується щонайбільше один раз і обслуговує обидва
резервні рівні.

1. **Стрічка джерела** — JSON-ендпоінти (DIM.RIA, flombu), вбудований payload
   (LUN) або картки списку (OLX, blago). Прив'язуємось до стабільних
   атрибутів (`data-testid`, `data-cy`) і до форми тексту, а не до
   згенерованих класів на кшталт `css-13vv2xi`.
2. **Сторінка деталей, детерміновано** — хук `BaseSource.enrich`:
   - **OLX** (`realty/sources/olx.py`) — сторінка оголошення віддає параметри
     списком «Ключ: Значення» (`Кількість кімнат: 3 кімнати`,
     `Вид об'єкта: Новобудова`, `Поверх: 1`), серед них — власне поле
     **«Ремонт»** із семи значень, плюс опис.
   - **flombu** (`realty/sources/flombu.py`) — опису немає ні в стрічці, ні в
     JSON-версії сторінки, зате він є в HTML: блок одразу після заголовка «Опис».
   - **LUN** (`realty/sources/rieltor.py`) — LUN агрегатор, і його
     `original_url` веде на сайт-першоджерело, майже завжди rieltor.ua
     (143 зі 144 зібраних оголошень). Картка rieltor.ua має пряме поле
     **«Загальний стан квартири»**, якого в payload LUN немає взагалі.
     `rieltor.py` — не джерело: власної стрічки ми там не читаємо, це лише
   - **DIM.RIA** (`realty/sources/domria.py`) — особливий випадок: рівень 2 йде
     не по нові поля, а по ті самі, яких **не віддає API**. JSON-ендпоінт
     `realty/data/{id}` повертає `characteristics_values` порожнім, а
     HTML-сторінка несе ті самі характеристики вже з людськими назвами — у
     `window.__INITIAL_STATE__`. Там лежить пряме поле
     **«стан квартири»** (дизайнерський ремонт / косметичний / хороший /
     потребує ремонту) і мітка ринку в `mainCharacteristics`.

   `enrich` не має лише **blago** — каталог планувань забудовника, де сторінка
   деталей нових полів не додає.

   > **Пастка DIM.RIA.** Поруч зі станом квартири лежить група
   > «Зовнішня обробка» зі значенням «без оздоблення» — це про **фасад**, а не
   > про квартиру. Без перевірки назви групи такі оголошення хибно ставали б
   > «без ремонту», тож `parse_detail` читає стан лише з групи
   > «Характеристика приміщення». Це зафіксовано окремим тестом.

   > **Особливість payload LUN.** Довгі описи RSC-потік зберігає окремими
   > записами, а в об'єкті оголошення лишає посилання: `"text": "$31"`.
   > Записи йдуть впритул, без переносу рядка (`31:T7e7,<текст>32:T807,<...>`),
   > а їх довжина вказана **в байтах UTF-8**. `resolve_text_rows` розбирає їх
   > послідовно; без цього опис губився приблизно в чверті оголошень LUN.
3. **LLM-фолбек** — якщо критичних полів бракує і після сторінки деталей,
   очищений текст іде в Claude API (`realty/llm.py`). Модель **доповнює лише
   порожні поля** й ніколи не перезаписує те, що вже розібрав парсер.

   Рівень платний, тому підпорядкований економії:

   | правило | як реалізовано |
   |---|---|
   | тільки як резерв | тригер — відсутність `price` / `rooms` / `area_total`; стан і ринок виклику не варті |
   | найдешевша модель | `claude-haiku-4-5` ($1/$5 за млн токенів); Sonnet/Opus для парсингу заборонені |
   | ніякого HTML у запиті | `clean_html` вирізає `script`, `style`, `svg`, шапку, футер, меню, банери — 380 КБ сторінки стискаються до ~2 500 символів (150×) |
   | стеля обсягу | `LLM_MAX_CHARS=2500`; при переповненні лишаються рядки з ціною, площею, кімнатами та опис, а не перші N символів поспіль |
   | стисла відповідь | строга схема (`output_format`), `max_tokens=512`, жодного Markdown |
   | без повторів | сторінка, яка вже дала помилку, у межах прогону не запитується вдруге |
   | стеля викликів | `LLM_MAX_CALLS=25` на прогін |
   | видимість витрат | у звіті: кількість викликів, токени й вартість у доларах |

   Без ключа Anthropic рівень вимикається **до** першого мережевого запиту,
   а не після нього.

   На зібраних 573 оголошеннях модель знадобилася **один раз** — для пентхауса,
   де OLX не заповнив кількість кімнат: 2 267 вхідних + 51 вихідний токен,
   $0.0025. Решта 99.8% розібрано безкоштовно.

Сторінка деталей завантажується тільки тоді, коли в записі є прогалина **і**
джерело має чим її закрити: для `blago`, який `enrich` не перевизначає, без
ключа Anthropic жодного зайвого запиту не буде (перевірено тестом).

### Звідки береться `condition`

Порядок правил у `classify_condition` (`realty/normalize.py`):

1. **Заперечення першими** — «без ремонту», «сирець», «чорнова обробка».
   Інакше «без ремонту» спрацювало б як «ремонт».
2. **Ознаки готовності** — «євроремонт», «заїжджай і живи», а також теги RIA
   «З обробкою» й «Обставлена».
3. **Некеровані ЖК** — якщо ринок первинний і в тексті сказано, що будинок ще
   не зданий («здача заявлена в 1 кварталі 2028»), стан вважається «без
   ремонту»: квартири фізично ще немає. Правило вмикається лише разом із
   підказкою про ринок і поступається явній згадці ремонту.

Якщо сайт має **власне поле стану**, воно має пріоритет над усіма правилами
вище: пряме значення точніше за здогад із тексту. Такі поля є у трьох джерел,
і всі три словники взяті з самих сайтів, а не вгадані:

| джерело | поле | значення |
|---|---|---|
| OLX | «Ремонт» | авторський проект · євроремонт · косметичний ремонт · житловий стан · після будівельників · під чистову обробку · аварійний стан |
| DIM.RIA | «стан квартири» | дизайнерський ремонт · євроремонт · косметичний · хороший · потребує ремонту |
| rieltor.ua | «Загальний стан квартири» | з ремонтом · без ремонту · частковий ремонт |

Жодне зі значень OLX не ловиться текстовими шаблонами: «Житловий стан» не
містить слова «ремонт», а «Під чистову обробку» — це протилежність «чорновій
обробці», хоч формулювання й схожі.

Значення rieltor.ua «Частковий ремонт» свідомо не мапиться: у бінарній схемі
воно не є ні готовністю до проживання, ні сирцем, тож лишається `unknown`.

Те, що не потрапило під жодне правило, лишається `unknown` — у веб-інтерфейсі
це окреме значення фільтра. Здогади сюди не пишемо.

### Режими збору

| режим | коли | що робить |
|---|---|---|
| `fresh` (типово) | щоденний фон | іде по найновіших; джерела з датним сортуванням зупиняються на першій сторінці без новинок |
| `full` | одноразово | знімає стелю глибини, зберігає прогрес посторінково |

Рання зупинка дозволена лише **DIM.RIA** і **OLX**: перший типово віддає
спадний `realty_id`, другому явно передаємо `search[order]=created_at:desc`.
**LUN** робочого параметра сортування за датою не має — у його стрічці новинки
перемішані зі старими, тож рання зупинка там була б хибною і працює лише
стеля сторінок.

### Фоновий розклад

```bash
python cli.py schedule install --hours 3   # launchd, кожні 3 години
python cli.py schedule status              # стан, останній код виходу, помилки
python cli.py schedule uninstall
python cli.py schedule cron                # рядок для crontab
python cli.py schedule worker              # вбудований воркер, без launchd
```

> **Проєкт має лежати поза `~/Desktop`, `~/Documents` і `~/Downloads`.**
> macOS (TCC) не пускає туди фонові агенти launchd без Full Disk Access:
> агент падає з `Operation not permitted` ще до запуску скрипта, причому
> мовчки — власний лог агента теж опиняється в закритому каталозі, тому він
> пишеться в `~/Library/Logs/realty/`. `schedule install` перевіряє
> розташування й попереджає. Саме через це проєкт живе в `~/realty`.
> Якщо перенести його не можна, лишається `schedule worker` — він успадковує
> права термінала, з якого запущений, але не переживає перезавантаження.

### Повний історичний збір

```bash
.venv/bin/python scripts/full_scrape.py --dry-run   # план і оцінка часу
.venv/bin/python scripts/full_scrape.py             # повний прогін
.venv/bin/python scripts/full_scrape.py --reset     # почати з нуля
```

Прогрес пишеться в `data/full_scrape_state.json` **на кожній сторінці**, тож
перерваний прогін продовжується з тієї сторінки, де зупинився. `Ctrl+C`
завершує поточне джерело й зберігає стан; повторний — виходить негайно.

### Міжплатформна дедуплікація

```bash
python cli.py dedup --dry-run   # порахувати без запису
python cli.py dedup             # звести в майстер-записи
```

Одна квартира на кількох сайтах стає одним записом `Property` з масивом
посилань на всі оригінали (`/api/properties`) і спільною історією цін
(`/api/properties/{id}/prices`).

**Чому не жорсткий складений ключ.** Адресу з вулицею та будинком дають лише
DIM.RIA і LUN; OLX і flombu вказують саме місто, blago — назву ЖК. Тому пари
оцінюються за сукупністю ознак, а об'єднання відбувається при `score ≥ 6`:

| ознака | вага |
|---|---|
| різна кількість кімнат, площа поза допуском 0.6 м², різний поверх, різні вулиці | заборона |
| збіг вулиці | +3, ще +3 за спільний номер будинку (−6 за різні) |
| площа з точністю 0.3 м² | +2 |
| ціна в межах 3% | +3 (до 10% — +1, понад 25% — −2) |
| збіг району | +1 |

Три знахідки, які визначили алгоритм:

1. **Порядок слів різний.** LUN пише «Героїв Миколаєва вул., Будинок 3,
   Тисменицька», DIM.RIA — «вул. Героїв Миколаєва, 3». Адреси порівнюються як
   набори слів із перетином ≥ 0.65, а не рядками.
2. **Номер будинку не один.** «Княгинин, 44 корпус 13» і «Будинок 13» — той
   самий будинок. Тому з адреси беруться **всі** числа, а збігом вважається
   непорожній перетин множин.
3. **Безадресне оголошення робить місток.** Запис OLX без адреси однаково
   схожий на дві квартири на різних вулицях, і наївне об'єднання пар
   транзитивно зливало Івасюка 86 з Височана 18. Тому спершу будуються якорі
   з адресних оголошень, і лише потім безадресні приєднуються — кожне
   щонайбільше до одного якоря.

### Дозбір наявних записів

Коли новий рівень вилучення з'являється після того, як частину оголошень уже
зібрано, у стрічці джерела їх може вже не бути. Для цього є окрема команда:

```bash
python cli.py backfill              # усі джерела
python cli.py backfill --sources olx --limit 100
```

Вона бере з бази записи з прогалинами — критичними або бажаними — і проганяє
їх через рівні 2-3.

## Веб-інтерфейс

Мінімалістичний макет у «редакційному» дусі: жодних вкладених карток і рамок —
структуру тримають волосяні лінії, відступи й типографіка. Один акцентний
колір працює тільки на посиланнях і активному сортуванні; стан житла
позначається крапкою, а не яскравим бейджем.

- **Зведення** показує **медіани**, а не середні: кілька дорогих об'єктів
  зміщують середнє так, що воно перестає описувати типову пропозицію
  (у зібраних даних середнє за м² — $1301, медіана — $1134).
- **Фільтри застосовуються одразу**, без кнопки. Стан житла — головний фільтр
  за ТЗ — винесено в сегментований перемикач. Порожні поля не потрапляють
  в адресу, тож посилання лишається читабельним:
  `?condition=needs_repair&sort=date_desc`.
- **Сортування** — за ціною, кімнатами, $/м² і датою; активний напрямок
  підсвічено в заголовку колонки.
- **Ціна за м²** супроводжується відхиленням від медіани (`+56% від медіани`),
  якщо воно перевищує 10% — так одразу видно, де оголошення випадає з ринку.
  Це ж робить очевидними й аномалії в даних самих джерел.
- **Дати** відносні: «сьогодні», «3 дні тому», «2 тиж. тому».
- **`Не вказано`** — окреме значення, а не порожнє місце: під таблицею
  пояснено, що продавець не заповнив це поле в джерелі.
- **Адаптивність**: на вузькому екрані рядки таблиці стають картками
  (ціна і $/м² зверху, далі адреса, параметри, стан).
- **Світла й темна теми** — за системним налаштуванням.
- JSON тих самих даних: `/api/listings`, зведення — `/api/stats`,
  схема — `/api/docs`.

## Актуальність оголошень

Без цього база лише зростає: продана квартира лишається в ній назавжди як
активна, і статистика рахується по суміші живих і знятих оголошень.

```bash
python cli.py verify --limit 200            # перевірити порцію
python cli.py verify --sources domria,olx
```

Сигнал у кожного сайту свій — з'ясовано на неіснуючих ідентифікаторах:

| сайт | що означає «знято» |
|---|---|
| DIM.RIA | 404 на сторінці оголошення (JSON-API тут не годиться — віддає 200 навіть на вигаданий id) |
| LUN (rieltor.ua) | 410 Gone |
| flombu | 404 після слідування редіректам |
| OLX | 404, потрібен браузер |
| blago | **сигналу немає** — і живе, і вигадане планування дають 200, тому джерело не перевіряється |

**Знімаємо з продажу лише за явним 404 чи 410.** Будь-яка інша відповідь —
привід нічого не робити: rieltor.ua починає віддавати 403 після кількох
десятків швидких запитів, і якби блокування вважалось «оголошення зникло»,
перевірка вимикала б живі записи пачками. Після п'яти відмов поспіль джерело
перестає чіпатись до наступного разу.

Найточніший спосіб — не перевірка посилань, а **повний обхід**: якщо джерело
віддало всю свою видачу, а оголошення в ній не було, воно там більше не
публікується (`sweep_after_full_run`). Спрацьовує лише за успішного прогону:
після збою список побаченого неповний.

### Ручна позначка

У таблиці кожен рядок має перемикач:

- **клік** — позначити вручну актуальною або неактуальною;
- **Alt+клік** — зняти позначку й повернути під автоматичне визначення.

Ручне рішення завжди сильніше за автоматичне (`manual_active` перекриває
`is_active`), тож наступна перевірка посилань його не затре. Крапка біля
підпису означає, що стан виставлено людиною.

Фільтр «Актуальність» має три значення: `Актуальні` (типово), `Неактуальні`,
`Усі`. Типово зняті з продажу не показуються й не потрапляють у статистику.

## Сторінка стану системи

`http://127.0.0.1:8000/status` — моніторинг і ручне управління збором.
Оновлюється сама кожні 5 секунд.

- **Фоновий воркер** — `Працює` / `Очікує` / `Не відповідає`, час останнього
  сигналу, лічильник сигналів. Якщо сигналу немає довше за `WORKER_DOWN_MIN`
  (типово 240 хв), сторінка показує тривогу.
- **Джерела** — зібрано, покриття, скільки лишилось, частка успішних запитів,
  блокування за 24 год, час останнього успішного прогону.
- **Якість даних** — оголошення, унікальні квартири, склеєні дублікати,
  скільки ще не пройшло дедуплікацію.
- **Витрати на модель** — виклики, токени, вартість у доларах.
- **Кнопки** — глобальний запуск і окремий для кожного джерела.

Ендпоінти: `GET /api/status`, `GET /api/status/runs`,
`POST /api/status/run` з тілом `{"source": "olx"}` або `{"source": "all"}`.

### Дві речі, важливі для довіри до цифр

**Телеметрія живе в окремій базі** `data/ops.db`, не в `realty.db`. Дані
спостереження за краулером не змішуються з самими оголошеннями: основну базу
можна перебудувати чи перенести, не втративши історії роботи, і навпаки.

**Кнопки запускають окремі процеси** (`cli.py scrape --trigger manual`), а не
виконують збір усередині вебсервера. Помилка збору не може повалити сторінку,
а повторний запуск того самого джерела відхиляється з кодом 409.

Час усюди віддається з явною зоною UTC. Без цього браузер читає мітку як
місцеву — на дашборді моніторингу це давало похибку в кілька годин.

## Налаштування (`.env`)

| Змінна | Призначення |
|---|---|
| `ANTHROPIC_API_KEY` | вмикає LLM-фолбек |
| `LLM_MODEL`, `LLM_MAX_CALLS` | модель і запобіжник витрат (типово `claude-opus-5`, 25) |
| `REQUEST_DELAY` | пауза між запитами до одного хоста, с |
| `CACHE_TTL` | час життя кешу відповідей, с (0 — вимкнути) |
| `PROXY_URL` | проксі для HTTP-клієнта і браузера |
| `SOURCES` | обмежити перелік джерел |
| `USD_UAH_RATE` | резервний курс, якщо API НБУ недоступне |

## Про доступ до сайтів

Мережевий шар — це коректний HTTP-клієнт: реалістичні заголовки, ретраї з
експоненційною паузою, обмеження темпу на хост і кеш відповідей, щоб не
смикати джерело двічі за одне й те саме. Обходу WAF, розгадування CAPTCHA
та підміни відбитків браузера тут немає; де сайт віддає дані лише реальному
браузеру, використовується звичайний Chromium.
