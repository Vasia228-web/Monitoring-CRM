# Як користуватися системою

Система живе на **ноутбуці з Fedora** (SSH лише через Tailscale:
`u@100.114.183.106`) і працює сама: збирає
кожні 3 години, робить бекап щодня, а коли їй погано — пише в Telegram.
Вмикати чи запускати нічого не треба, навіть після перезавантаження.

## Відкрити сайт

**На самій Fedora:** http://localhost:8000 — логін і пароль ті, що в `.env`.

**Ззовні** (з телефона, з іншого міста) — буде за доменом. Тимчасова адреса
Cloudflare у цій мережі не працює: провайдер блокує `trycloudflare.com`
(перевірено з обох машин). Коли з'явиться домен — два рядки в `.env` і
перезапуск однієї служби, адреса прийде в Telegram.

| Сторінка | Що там |
|---|---|
| `/` | усі квартири, фільтри, сортування |
| `/processing` | тільки взяті в роботу |
| `/analytics` | ціни по сегментах, ліквідність |
| `/status` | чи працює збір, бекапи, тривоги, ручні запуски |

## Що можна помацати

**Взяти квартиру в обробку** — кнопка «Взяти» у крайній правій колонці.
Об'єкт з'явиться на сторінці «В обробці». Щоб прибрати — та сама кнопка ще
раз. **Запис при цьому не видаляється**, просто повертається в загальний список.

**Аналіз конкретної квартири** — посилання «аналіз об'єкта →» під адресою.
Головна цифра там: на скільки відсотків дорожче або дешевше за схожі.

**«Дані не збігаються»** — кнопка на картці квартири. Натиснута скарга
потрапляє в список на `/status`: по ньому видно, які правила ламаються частіше.

**Посилання можна передавати.** Усі фільтри й сортування записані в адресу.

## Коли щось не так

Спершу — Telegram: система сама пише, якщо збору немає довше, ніж зазвичай,
якщо джерело перестало приносити записи, якщо сайт почав блокувати запити або
якщо не вдався бекап. **Мовчання означає, що все гаразд** (крім випадку, коли
вимкнений сам ноутбук — тоді мовчить і сторож).

Команди на Fedora, якщо захочеться подивитись самому:

```bash
systemctl --user list-timers 'realty-*'      # коли наступні запуски
journalctl --user -u realty-cycle -n 40      # що було в останньому циклі
systemctl --user start realty-cycle.service  # запустити збір негайно
cd ~/realty && .venv/bin/python cli.py backup status   # стан бекапів
cd ~/realty && .venv/bin/python cli.py watchdog --test # перевірити Telegram
```

Перезапустити сайт, якщо сторінка не відкривається:

```bash
systemctl --user restart realty-web
```

## Бекапи

Щодня о 04:30 і раз на добу в циклі: копія бази, перевірка, що вона
відновлюється, і вивантаження **поза машину**. Локально лишаються 7 останніх.

Відновити з архіву (створює НОВИЙ файл, робочу базу не чіпає):

```bash
cd ~/realty && .venv/bin/python cli.py backup restore data/backups/АРХІВ.tar.xz /tmp/перевірка.db
```

## MacBook

Збір там вимкнено (файл `data/COLLECTOR_OFF`), агент розкладу вивантажено.
База лишається на місці недоторканою — це ще одна копія на момент переїзду.
Дві машини ніколи не збирають одночасно: інакше історія цін розійдеться на
дві різні версії.
