# Верифікація джерел

Ізольовані скрипти, якими перевірялося кожне джерело **до** інтеграції в
пайплайн. Лишені навмисно: коли сайт змінить розмітку чи API, швидше
перезапустити пробу, ніж дебажити весь пайплайн.

| Скрипт | Що з'ясував |
|---|---|
| `p_ria.py` | склад полів картки `dom.ria.com/realty/data/{id}` |
| `p_ria_geo.py` | мапа `state_id` → область; Івано-Франківська = **15** |
| `p_ria_city.py` | `city_id` міста = **15**; повний дамп полів картки |
| `p_olx.py` | HTTP-клієнти отримують 403 від CloudFront (HTTP/1.1 і HTTP/2) |
| `p_olx_pw.py` | реальний Chromium відкриває ту саму сторінку: 200, 52 картки |
| `p_flombu.py` | `/uk/estate_deal_sales.json` — формат JSON:API |
| `p_flombu2.py` | склад `meta`, пагінація |
| `p_flombu3.py` | фільтри працюють лише з префіксом `filter[...]` |
| `p_lun.py` | картки LUN мають хешовані класи — на них не спиратись |
| `p_olx_params.py` | повний перелік ключів картки OLX; серед них — «Ремонт» |
| `p_ria_detail.py` | HTML-сторінка DIM.RIA має характеристики, яких немає в JSON-API |
| `p_ria_chars.py` | словник груп `secondaryParams`; «стан квартири» — у групі «Характеристика приміщення», «Зовнішня обробка» стосується фасаду |
| `p_rieltor.py` | картка rieltor.ua має поле «Загальний стан квартири» на 11/11 сторінок; значення: «З ремонтом», «Без ремонту», «Частковий ремонт» |
| `p_lun2.py`, `p_lun3.py` | RSC-payload Next.js містить повні об'єкти оголошень |

Запуск: `.venv/bin/python probes/p_ria_geo.py`

## Аудит даних (етап 9)

| Скрипт | Що з'ясував |
|---|---|
| `p_audit_fields.py` | звірка 150 записів із тим, що заявляє сайт: помилок у стані 0/50, ринку 1/82, кімнатах 0/144, ціні 0/58 |
| `p_why_renovated.py` | найдешевші «з ремонтом» позначені так самим продавцем через параметр OLX «Ремонт:», а не нашим парсером |
| `p_olx_price.py` | 59 із 60 сторінок OLX показують ціну в доларах, а ми зберігаємо гривневу з картки: медіана розходження −0.04%, окремі випадки до −13.7% |
| `p_audit_report.py` | зведення аудиту в таблицю |
